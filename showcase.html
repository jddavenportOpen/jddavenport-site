01 · Live system view

The AI operating system I run my work on

Snapshot · 2026-11-26

My own agent system. I started building it in February 2026 and have built 100+ agents for it. One orchestrator hands out work and a durable job queue holds it. Email or messages to other people pass one gate that waits for my yes by default, apart from three narrow approvals I signed. It runs on a schedule on a Mac mini and republishes its own inventory when it ships.

The three live counts come from an inventory the system writes about itself. A background job is one scheduled macOS LaunchAgent or cron entry. A watchdog is a job that checks other work and alerts when it fails. A shipped-work entry is one line in the system's work log.

How work moves
  1. A request lands: a Telegram voice note, a cockpit message, or a scheduled job firing on its own.
  2. The orchestrator triages it and picks the agent that owns it. The router picks the model.
  3. It becomes a job row in Postgres. A durable runner claims it, and agents coordinate over the bus.
  4. An agent does the work, in its own git worktree if it touches code, reading memory and state as it goes.
  5. Anything irreversible or outward-facing stops at the gate until I say yes.
  6. The result ships through the relay with a receipt. Watchdogs keep checking after it lands.

The map is drawn by hand from the running system: component names are real, hostnames and credentials are left out. The counts load live from /api/metrics, a server-side filter over the inventory the system republishes on its own. It forwards numbers only, never names or contents. If that request fails you see the snapshot from 2026-11-26.
