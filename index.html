How I run production AI agents.

Nerve Center is my own multi-agent system: 30+ agents in daily production, 100+ built over time. The drawing shows structure only. Every part fails eventually, so every failure needs a catch; the lettered marks are four of them.

Read the drawing as text
  1. The operator (me, on phone or desktop) works through the cockpit, a TypeScript UI.
  2. The cockpit puts work on a message bus, which queues it. A frozen modal here is caught by the watchdog (C).
  3. A supervising daemon runs the agent sessions and restarts any that die (A).
  4. Inside the sessions, one CEO agent fans work out to 30+ specialists in daily production.
  5. Sessions retrieve from a memory graph first, and read and write durable state, where tombstones reject a stale tab’s write (B).
  6. Anything that speaks for me to another person (email, messages, posts) waits at one send gate for my yes (D).
  7. A watchdog layer wraps everything and measures work done, not uptime.
  1. A

    A: Sessions die. A guard brings them back.

    Agent sessions crash and get killed mid-task. The supervising daemon notices the missing session and restarts it from durable state, so the work resumes instead of quietly vanishing.

  2. B

    B: A stale tab cannot overwrite the present.

    A closed session leaves a tombstone. When an old browser tab tries to write to it later, the write is rejected rather than bringing a dead session back to life.

  3. C

    C: A frozen modal cannot stall the queue for long.

    One blocking dialog can freeze a session and everything queued behind it. The watchdog measures work completed, not uptime, so it sees the stall, clears it, and the queue drains again.

  4. D

    D: Nothing speaks for me without passing the gate.

    Agents draft email, messages and posts. Anything that speaks for me to another person waits at one gate for my yes. None of it skips the gate.

The incidents behind these guards, and what changed after each one, are written up in the agent safety case study ↗.
